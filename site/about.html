HOW I GOT HERE

I’ve followed the work
that needed doing.

I did not set out to collect disciplines. I kept taking responsibility for the next part of the problem.

I started freelancing in 2014, mostly writing PHP and Python backends. Agency and lead-development work taught me how to ship for real clients, work inside existing systems and take responsibility beyond the original brief.

That range grew out of the work. On one ANPR platform, the right answer was to move from EC2 and RDS to S3, SQS and Lambda. The result was a more reliable system that cost 40% less to run. That project stuck with me because it was a reminder that good engineering is about improving the situation, not showing off the technology.

The work has since taken me through data security and AWS data engineering. Today I work on network automation around Cisco ISE and ServiceNow. Along the way I have kept building interfaces, dashboards and tools because I like seeing how the whole thing fits together—not only the service behind it.

WHAT I WANT NEXT

I’m not trying to force that experience into one perfect job title. I’m looking for good people, a worthwhile problem and enough ownership to do the job properly. I value teams that can discuss trade-offs honestly and care what happens after the software ships.

A PROJECT OF MY OWN

I wanted a better HeadRush editor,
so I started building it.

The hardware is powerful, but some everyday jobs are awkward on its screen and the supplied web editor did not cover everything I needed. I started by mapping the undocumented API, then turned that work into the desktop application I wanted to use.

It has let me do the whole job—work out which problems are worth solving, design the interactions, build the application, test it with a real device and document it for other musicians. It is the clearest example of the way I like to work.

DEVICE APIUnderstand the thing properly

Mapped an undocumented API and checked assumptions against a real HeadRush device.

PRODUCTChoose problems worth solving

Focused the product on TonePilot, StageHand, Change History and the jobs the original editor makes difficult.

APPLICATIONBuild it end to end

Combined React, TypeScript and Tauri with device integration, recovery paths, state modelling and desktop packaging.

REAL USETest where it matters

Added automated coverage and responsive checks, then verified the important workflows with the hardware itself.
